# 서버 보상 콜백 URL

이 페이지에서 하는 일: 실제 포인트 지급 경로인 **서버 보상 콜백**을 구현할 때, 앱에서 설정한 값이 콜백과 어떻게 이어지는지와 꼭 지켜야 할 것을 정리합니다.

---

## 언제 필요한가

사용자에게 개발사 포인트를 지급하는 **모든 개발사에 필요**합니다(필수).
사용자가 광고 참여를 완료하면 TNK 서버가 개발사 백엔드의 콜백 URL 을 호출하고, 개발사는 그 요청을 검증한 뒤 자사 포인트를 지급합니다.

| 순서 | 누가 | 무엇을 |
|:-:|---|---|
| 1 | 사용자 | 오퍼월에서 광고 참여를 완료합니다 |
| 2 | TNK 서버 | 개발사 백엔드의 콜백 URL 을 호출합니다 |
| 3 | 개발사 백엔드 | 요청을 검증하고 포인트를 지급한 뒤 `200` 을 응답합니다 |
| 4 | 앱 (선택) | 보상 알림이 오면 개발사 서버에서 잔액을 다시 불러와 화면을 갱신합니다 |

콜백 URL 의 등록·변경은 담당자에게 요청하세요.

> 📖 **전체 규격은 [외부 매체 연동 가이드 — 2.9 광고 적립 URL 호출](https://github.com/tnkfactory/s2s-api-rwd#29-%EA%B4%91%EA%B3%A0-%EC%A0%81%EB%A6%BD-url-%ED%98%B8%EC%B6%9C) 을 따릅니다.**
> 전체 파라미터 목록, 검증 코드 예시(Java), 광고 유형 코드가 그 문서에서 최신 상태로 관리됩니다.
> 이 페이지는 **SDK 연동 관점에서 알아야 할 것**만 정리합니다.

> 기존 네이티브 SDK 를 사용 중인 개발사라면 **이 계약은 변경되지 않았습니다.**
> 기존 콜백 구현을 그대로 사용하시면 됩니다.

---

## SDK 와의 연결점

앱에서 설정한 값이 콜백 파라미터로 이어집니다. **이 대응만 맞으면 나머지는 서버 간 계약입니다.**

| 앱에서 | 콜백에서 |
|--------|---------|
| `setUserName` 에 넘긴 사용자 식별값 | `md_user_nm` |
| 앱 등록 시 함께 발급된 **앱 키** — 확인 위치는 [APP ID 발급받기](../publisher/app-id.md) 의 '2. APP ID 확인' 항목을 참고하세요 | `md_chk` 검증에 사용하는 `app_key` |

> ⚠️ **오퍼월을 열기 전에 반드시 `setUserName` 을 호출하세요.**
> 호출하지 않고 오퍼월에 들어가면 콜백의 `md_user_nm` 이 비어 있거나 빠져서, 보상을 받을 사용자를 알 수 없습니다.
> 사용자를 알 수 없으면 아래 2번 검증으로도 사용자를 확인할 수 없습니다.

> ⚠️ 로그인 전 임시값으로 오퍼월에 진입했다가 나중에 `setUserName` 을 바꾸면,
> 그 사이 발생한 보상이 임시값으로 지급되어 회수할 수 없습니다.
> 오퍼월 진입은 사용자 식별값이 확정된 뒤로 미루세요.

> 💡 `setUserName` 값이 바뀌면 개인정보 수집 동의도 초기화됩니다. 앱에서 `setAgreePrivacy(true)` 를 호출하지 않았다면 오퍼월이 동의 팝업을 다시 띄웁니다.
> 자세한 내용은 [Android 7. 개인정보 설정](../android/privacy.md) · [iOS 7. 개인정보 설정](../ios/privacy.md)을 참고하세요.

`app_key` 는 **앱에 포함하지 말고 개발사 백엔드에만 보관**하세요.

## 구현 시 반드시 지킬 것

1. **`seq_id` 로 중복 처리를 차단하세요.**
   재시도 정책 때문에 같은 `seq_id` 가 여러 번 도착할 수 있습니다.
   이미 처리한 건이라면 지급하지 말고 **200 을 응답**하세요.

2. **`md_chk` 를 검증하세요.** `MD5(app_key + md_user_nm + seq_id)` 와 일치하지 않으면 버립니다.
   구현 예시는 위 정식 가이드에 Java 코드로 있습니다.

3. **지급이 확정된 뒤에 200 을 응답하세요.**
   200 이 아니면 TNK 서버가 5분 단위·1시간 단위로 최대 24시간 동안 반복해서 호출합니다.
   먼저 200 을 응답하고 나중에 지급하다 실패하면 재시도를 받을 수 없습니다.

## 클라이언트 콜백과의 관계

SDK 의 `setRewardListener` 는 **UI 갱신용**입니다. 잔액 표시를 새로 그리거나 토스트를 띄우는 용도로만 쓰세요.
클라이언트 콜백만 믿고 지급하면 위·변조로 부정 적립이 발생합니다.

| | 용도 | 어떤 보상에 오나 | 신뢰 |
|---|---|---|---|
| `setRewardListener` (앱) | 즉시 UI 반응 | 오퍼월 화면 안에서 바로 지급이 확정된 보상에만 | ❌ 지급 근거로 쓰지 않음 |
| 서버 콜백 (백엔드) | **실제 포인트 지급** | 지급이 확정된 보상 전체. 광고주 확인 뒤 나중에 확정되는 보상도 포함 | ✅ 정본 |

광고주 확인 뒤 나중에 확정되는 보상은 앱의 리스너로는 오지 않고 **서버 콜백으로만** 옵니다. 그래서 잔액은 항상 서버 콜백으로 적립한 값을 기준으로 관리하세요.
리스너가 오는 보상의 종류는 플랫폼별 문서([Android](../android/reward.md) · [iOS](../ios/reward.md))를 참고하세요.
